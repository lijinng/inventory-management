Data flow

How a filter change on the dashboard becomes updated numbers on screen.

  1. User changes a filter. FilterBar updates the shared refs in useFilters (period, location, category, status).
  2. View reacts. The view calls getCurrentFilters(), which maps period to a month param.
  3. API client builds the request. api.js appends only non-all params and calls GET /api/....
  4. FastAPI filters in memory. apply_filters and filter_by_month narrow the lists loaded from JSON.
  5. Pydantic validates the response and FastAPI returns JSON.
  6. View renders. Raw data is stored in refs; derived totals and chart series are computed properties.

Observations

Things worth knowing found while reading the code.

  • api.js calls /tasks and /purchase-orders (create, delete, toggle, lookup), but server/main.py defines no routes for them. Only the GET endpoints above exist, so those client calls would return 404.
  • The API base URL is hard-coded to http://localhost:8001/api in api.js, and CORS allows every origin. Both are fine for a local demo, not for deployment.
  • All data is read once at startup and never written back, so state resets on every server restart. Inventory has no time dimension, so it ignores the month filter.
  • Backlog.vue exists but is not registered in the router; backlog data surfaces through the dashboard and its detail modal.
